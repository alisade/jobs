FDE / SME - AWS Cloud Engineer with Agentic AI

6-week plan plus an optional add-on week: Bedrock, AgentCore, RAG and Neptune, multi-tenant identity, Quick Sight embedded analytics and FDE practice. Weekdays ~2-3 h, weekends one long block for the workbook exercises and the portfolio. Checkboxes save in this browser.

Overview

The role: a forward deployed engineer and subject-matter expert for AWS cloud with agentic AI, hybrid three days a week onsite in Sparks, Maryland. You sit with customer teams and build and debug production systems on Amazon Bedrock and AgentCore, RAG with vector stores and knowledge graphs on Neptune, multi-tenant identity (IAM, Cognito, tenant-to-user mapping, authorization boundaries), Quick Sight analytics and embedded dashboards, and Lambda / API Gateway / DynamoDB event-driven backends. The job is rapid diagnosis against ambiguous requirements, then turning each one-off fix into a reusable pattern. The posting also asks for a self-rated skill matrix (see Interview prep).

Honest fit note. The posting says "must have created at least one production level solution using Amazon Bedrock and AgentCore". Today you probably do not meet that, so do not claim it: FDE interviews are live and a claimed production build gets probed down to error codes and quota numbers. Best option: ship a small, low-risk internal agent on Bedrock and AgentCore at work (deployed with IaC, real users, auth, logging, an owner). Fallback: the portfolio project below, deployed and kept running, described exactly as "a production-grade deployment I run, not a customer system"; ask the recruiter early whether that satisfies the requirement. The rest of the posting fits well: AWS depth, identity and diagnosis are the hard parts of an FDE job, and you have them.

How this applies to this role

AWS FDE with agentic AI: all seven areas apply, with no model training. The model is Bedrock behind your own loop or AgentCore Runtime, so most of the work is integration discipline and tenant safety.

  • Tools (1) and the loop (2): Converse toolConfig / toolUse / toolResult on Bedrock, and Gateway turning Lambda functions into MCP tools. Tools take the tenant from the verified token, never from arguments.
  • Context and caching (3): Bedrock prompt caching with a cachePoint after the static system prompt and tools; AgentCore Memory for what persists across sessions, namespaced per tenant and user.
  • Security (4): documents in a Knowledge Base are untrusted input. Guardrails help; server-side scoping (recipient allowlists, confirmation for writes, mandatory tenant filters, IAM session tags) is what actually stops exfiltration.
  • Evals (5): deterministic checks first (tool choice, groundedness of citations, tenant isolation, refusals, cost), several runs per case, a CI gate; Bedrock RAG evaluations and AgentCore Evaluations on top.
  • RAG (6): Knowledge Bases on S3 Vectors, OpenSearch Serverless or Aurora pgvector, metadata filters, GraphRAG on Neptune Analytics.
  • Observability (7): model invocation logging, AgentCore Observability traces in CloudWatch, token and cost per request.

Depth lives in Week 1 (Bedrock), Week 2 (AgentCore) and Week 3 (RAG). Practice: ai-c1 (agent eval harness as a CI gate) and ai-t1 (indirect prompt injection with an exfiltration channel), plus w1-c1 w3-c1 w3-t1.
