## 1. React + TypeScript front end

**Why:** "Develop full-stack applications using Python, TypeScript, and React" and "Strong hands-on
full-stack development experience with: Python, TypeScript, React". This is the largest gap.

**You already have:** TypeScript from CDK, so the type system and tooling (npm, tsconfig, eslint) are
familiar. The browser, components and UI state are not.

**Learn:**

## 3. Production GenAI application engineering

**Why:** "Design, develop, and deploy production-grade AI/ML and Generative AI applications" and "Own AI
engineering initiatives end-to-end, from technical design through implementation, testing, deployment,
and optimization."

**You already have:** the production half: deployment, observability, incident response, cost control on
AWS. What is new is the behaviour of the model call inside the app.

**Learn:**
- Streaming responses end to end (model to service to browser), and what breaks behind proxies and load balancers
- Rate limits, retries with backoff, timeouts, and a fallback model behind a small gateway interface

- Cost and latency budgets per request; logging tokens per call
- Reducing hallucination in product answers: ground on tool results, cite the source record, allow "I don't know"
- Prompt and model versioning: treat prompts as code, gate changes on the eval suite
- Tracing model calls (see [shared section 5](../../shared/details.md#5-verification-and-evals) for OpenTelemetry GenAI and evals)

**Links:**

## 4. Microservices architecture and trade-offs

**Why:** "Design and implement scalable solutions using microservice architecture and modern software
design patterns" and "Evaluate technical trade-offs and recommend appropriate architectures for
AI-enabled applications."

**You already have:** years of running microservices on EKS with Helm and ArgoCD, so you know the
operational cost of each extra service. Use that: it is the strongest argument in a trade-off discussion.

**Learn:**
- Service boundaries by business capability and data ownership; one database per service
- Sync (HTTP, gRPC) vs async (queues, events); sagas instead of distributed transactions
- Resilience patterns: circuit breaker, bulkhead, retry with backoff, idempotency keys
- API gateway and backend-for-frontend; where an LLM gateway fits
- Monolith first and strangler fig: when NOT to split
- AI-specific trade-offs: model calls are slow and expensive, so where you put them, cache them and stream them shapes the architecture
- Writing an ADR that records the options you rejected and why

**Links:**
- [Microservices (Martin Fowler and James Lewis)](https://martinfowler.com/articles/microservices.html)
- [MonolithFirst (Martin Fowler)](https://martinfowler.com/bliki/MonolithFirst.html)
- [Microservice architecture patterns (microservices.io)](https://microservices.io/patterns/microservices.html)
- [Cloud design patterns (Azure Architecture Center)](https://learn.microsoft.com/en-us/azure/architecture/patterns/)
- [Architecture Decision Records](https://adr.github.io/)
- [Docker Compose](https://docs.docker.com/compose/)

**Exercise:** Write three ADRs for the portfolio project: (1) catalog and assistant as separate services
or one, (2) streaming over SSE vs WebSocket vs polling, (3) model fallback in the assistant vs in a
separate gateway. Then practise a 20-minute whiteboard of the whole system out loud, including how it
fails.

## 5. Responsible AI: bias, safety, reliability

**Why:** "Apply responsible AI principles related to bias, safety, reliability, and ethical AI
development" and "Understanding of Responsible AI, including AI safety, bias, and ethical considerations."

**You already have:** the reliability and safety engineering habits: approval gates, least privilege,
verification before claims. The [shared LLM security section](../../shared/details.md#6-llm-security)
covers prompt injection.

**Learn:**
- Vocabulary interviewers use: NIST AI RMF functions (Govern, Map, Measure, Manage) and the GenAI profile's risk list
- Bias in a GenAI app: paired prompts that change only a name, dialect or demographic cue, and comparing outputs; why aggregate metrics hide this
- Fairness metrics at a basic level (demographic parity, equalized odds) and when they apply to classic ML vs GenAI
- Safety guardrails: input and output filters, topic limits, refusal behaviour, jailbreak mitigation
- Human oversight: when the user must confirm, when to hand off to a human
- Transparency: model cards and system cards, disclosing that the user is talking to AI
- Company principles you may be asked about (Google, Microsoft), and how to turn principles into tests

**Links:**
- [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)
- [NIST AI 600-1: Generative AI Profile (PDF)](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)
- [Evaluating and mitigating discrimination in language model decisions (Anthropic)](https://www.anthropic.com/research/evaluating-and-mitigating-discrimination-in-language-model-decisions)
- [BBQ: a hand-built bias benchmark for question answering](https://arxiv.org/abs/2110.08193)
- [Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993)
- [Fairlearn](https://fairlearn.org/)
- [Google AI Principles](https://ai.google/principles/)
- [Microsoft Responsible AI](https://www.microsoft.com/en-us/ai/responsible-ai)
- [Mitigate jailbreaks (Claude docs)](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks)
- [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)
- [NeMo Guardrails](https://github.com/NVIDIA-NeMo/Guardrails)

**Exercise:** Add 20 paired bias probes to the assistant's eval suite (for example "recommend a gift for
my coworker Emily" vs "... for my coworker Jamal", or the same question in standard and non-standard
English). Score price range, tone and refusal rate per group. Write a one-page system card: intended use,
out-of-scope uses, known limits, test results, and the human handoff path.

## 6. Integrating GenAI and agents into existing enterprise applications

**Why:** "Integrate emerging AI technologies and agentic capabilities into existing engineering workflows
and applications" and, preferred, "Hands-on experience integrating emerging GenAI technologies into
existing enterprise applications" and "building or integrating AI agents and agentic workflows."

**You already have:** you have wired agents into real enterprise systems through MCP (Jira, Spacelift,
AWS) with permission modes and approval gates. That is the same problem from the inside.

**Learn:**
- Rollout patterns: AI feature behind a feature flag, shadow mode, A/B against the existing flow, kill switch
- Strangler fig for adding an AI path next to a legacy one
- Agent frameworks and runtimes you may be asked to compare: Google ADK, LangGraph, Amazon Bedrock
  AgentCore, and the A2A protocol for agent-to-agent calls. Know what each one is for; you do not need
  depth in all of them
- Fitting into enterprise identity and data access: the agent acts with the user's permissions, not a superuser's

**Links:**
- [Strangler fig application (Martin Fowler)](https://martinfowler.com/bliki/StranglerFigApplication.html)
- [Agent Development Kit (ADK)](https://adk.dev/)
- [LangGraph overview](https://docs.langchain.com/oss/python/langgraph/overview)
- [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)
- [A2A protocol](https://a2a-protocol.org/)

**Exercise:** Write a two-page plan for adding the shopping assistant to an existing e-commerce site you
do not own: flag, shadow mode, success metrics, rollback, and which existing APIs the agent may call
with which permissions. Then build one of the assistant's tools a second time in ADK or LangGraph and
note what the framework gave you and what it cost.
