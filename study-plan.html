Local setup (done)

Repo at ~/git/jobs/commerce-agents, venv + npm installed, 1104 tests passing. Add your key to .env, then:

cd ~/git/jobs/commerce-agents
source .venv/bin/activate
python scripts/run_demo.py retail --all
# storefront :3000, portal :3100

Verify loop (use it all month)

ruff check . && ruff format --check . \
  && pytest && python scripts/check.py
python scripts/verify_all.py
python scripts/smoke_chat.py --vertical retail

Caching check: cache_read_input_tokens on turn_complete must be non-zero from turn 2.

AI integration fundamentals

Shared across all the study guides. No model training or data science: you call a model over HTTPS and engineer the software around it. Most of it is ordinary API work; the seven areas below are what is different, because an LLM is a probabilistic component, not a deterministic API.

SameWhat is just API integration

REST/SDK calls, auth, retries, timeouts, rate limits, streaming (SSE), cost metering. MCP is JSON-RPC with a tool/resource schema; an MCP server is a small service exposing your existing APIs as tools.

Tasks

  • Make a first Messages API call with streaming; read the usage block (input/output/cache tokens)
  • Read the MCP architecture overview: hosts, clients, servers, tools, resources, prompts

Materials

  • Claude API: Get started
  • Streaming messages
  • MCP architecture overview

Names, descriptions and input schemas decide whether the model picks the right tool with the right arguments. API design for a non-human caller.

Tasks

Materials

  • Tool use overview

2The agent loop

Model requests a tool, your code runs it, the result goes back, repeat. Stop conditions, structured errors the model can recover from, parallel tool calls.

3Context engineering and caching

What goes in the system prompt vs per-request context; staying within the context window; prompt caching for cost and latency (static prefix first, dynamic data after the breakpoint).

Tasks

  • Read the context engineering post and the prompt caching docs

Materials

4Security

Prompt injection from untrusted content; model output is untrusted input; the model can skip, fake or reorder tool calls, so enforcement lives server-side. Auth in front of MCP servers.

Tasks

  • Read the OWASP Top 10 for LLM applications
  • Read the MCP security best practices and authorization spec
  • Plant an injection in a tool result; confirm a server-side check (not the prompt) blocks the action

Materials

  • OWASP Top 10 for LLM Applications
  • MCP security best practices
  • MCP authorization

5Evals

Outputs vary run to run, so test with scored scenario suites ("did it call checkout without confirming?") rather than exact-match asserts. The least familiar part for most engineers.

Tasks

  • Read the guide on building empirical evaluations and test cases
  • Write a 10-case eval for your agent: code-graded checks plus one model-graded rubric; run it 3x

Materials

  • Create strong empirical evaluations

6RAG

Embeddings + a vector store (pgvector, OpenSearch, Azure AI Search), chunking, retrieval quality, citations. A data-pipeline and search problem, not model training.

Tasks

  • Read the embeddings docs and the contextual retrieval post
  • Embed ~50 docs into pgvector, retrieve top-k, answer with citations; measure hit rate on 10 questions

Materials

  • Embeddings
  • Contextual retrieval
  • Citations
  • pgvector

7Observability

Trace prompts, tool calls, token use and latency per turn. OpenTelemetry has GenAI semantic conventions for exactly this.

Tasks

  • Read the OTel GenAI semantic conventions (spans, metrics, events)

How this applies to this role

Forward Deployed Engineer: pure integration, all seven areas, no ML. anthropics/commerce-agents is a production-grade reference for every item: tool contracts and gates (1, 4), three runtimes of the same loop (2), byte-stable cached prefix (3), verification suites (5), grounding (6), per-call cache logging (7). Weeks 1-2 of this plan cover the rest.
