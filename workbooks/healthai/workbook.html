Healthcare payer AI/ML workbook

Hands-on coding, troubleshooting and design exercises set at Kestrel Health Plan (fictional), a payer with commercial, Medicare Advantage and Medicaid managed care lines: a PA intake API, gRPC criteria checks, X12 and FHIR mapping, LangGraph graphs with human review, hybrid retrieval, PHI de-identification and eval gates. One tab per study week, plus weekly self-exams. Everything grades locally and offline: no GCP account, no API keys, synthetic data only.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade healthai/<id> in Claude Code from the workbooks/ folder. Quiz answers save in this browser (localStorage key wb-healthai-v1).

How to work an exercise

  1. tools/doctor.sh healthai once: python3 and uv (uv downloads Python 3.12 into the track venv).
  2. Open the week tab, read the card, then the folder README.
  3. cd healthai/exercises/<id> && make setup (the first run builds healthai/.venv: LangGraph, FastAPI, Pydantic, grpcio, pytest), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade healthai/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; the design exercise is graded by rubric only (0/0 tests).

How the local stand-ins work

  • Models: scripted chat models and recorded outputs; no network call to any model API.
  • LangGraph runs for real with the in-memory or SQLite checkpointer, interrupts and Command(resume=...).
  • gRPC runs for real on localhost with grpc.aio; stubs are generated by grpcio-tools in make setup.
  • FHIR store, eligibility, Pub/Sub-style stages, Vector Search and logging exporters are small in-process fakes.
  • Data is synthetic and hand-written or generated with fixed seeds. ICD-10-CM codes are real public codes; procedures use generic labels or HCPCS Level II, never CPT descriptors.

PA intake API with typed requests and the CMS-0057-F clock

coding 2-3 h

healthai/w1-c1 · Advanced Python: Pydantic v2, FastAPI, asyncio

Scenario. Kestrel Health Plan's new PA intake API accepts only imaging requests, trusts every field and computes deadlines with naive datetimes. Make it a production edge: a Pydantic v2 discriminated union per request category, an eligibility call under asyncio.timeout, idempotent retries, lifespan-managed clients, and a CMS-0057-F decision clock that is right across DST and plan time zones.

Task

  • Finish the base model and three category models as a discriminated union
  • Rewrite compute_deadline: 72 elapsed hours, 7 calendar days on the plan's wall clock, QHP exclusion
  • Add the eligibility timeout (503), Idempotency-Key handling (replay and 409) and a lifespan handler

Acceptance criteria

  • All validation cases return 422; all three categories are accepted
  • Clock edge cases pass: DST both ways, plan time zone, UTC output, no federal clock for QHP
  • 503 on timeout within the bound; idempotent replay calls eligibility once
