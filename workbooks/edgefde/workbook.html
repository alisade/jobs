FDE (Edge AI) workbook

Hands-on coding, troubleshooting and design exercises set at Corvane Industrial's Dunmore pump plant (fictional), where you are embedded as a Tessellate Edge (fictional) forward deployed engineer: pipelines, signals, MLOps, edge AI, fleet operations, LLMs at the edge and locked-down networks. One tab per study week, weekly self-exams and one timed screen. Everything grades locally and offline: Python in a shared venv, in-process fakes for Kafka, the registry, the fleet and the CMMS, and a stub LLM that replays recorded turns.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade edgefde/<id> in Claude Code from the workbooks/ folder. Quiz answers and mock results save in this browser (localStorage key wb-edgefde-v1).

How to work an exercise

  1. tools/doctor.sh edgefde once: python3, uv, jq.
  2. Open the week tab, read the card, then the folder README.
  3. cd edgefde/exercises/<id> && make setup (the first run builds edgefde/.venv: numpy, scipy, scikit-learn, onnx, onnxruntime, skl2onnx, pydantic, pytest), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade edgefde/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; the design exercise is graded by rubric only (the grader reports 0/0 tests).

How the local stand-ins work

  • Kafka: an in-process broker with partitions, consumer groups, committed offsets and auto-commit.
  • Signals: synthetic accelerometer captures with known tones, gear mesh and bearing impacts, so every feature has a known answer.
  • MLOps and edge AI: a file-based registry fake; scikit-learn models exported with skl2onnx and quantized with ONNX Runtime on CPU.
  • Fleet and offline: simulated gateways with a fake clock, a SQLite buffer and a lossy uplink.
  • LLM: a stub client replaying recorded OpenAI-compatible turns (the shape Ollama and llama.cpp serve). No API keys.
  • Locked-down network: an evidence bundle (pip/uv logs, s_client captures) and real config files you fix.

Self-exam

  • Weekly sets (75 questions): week 1: 10, week 2: 11, week 3: 10, week 4: 10, week 5: 10, week 6: 11, week 7: 5, AI page: 8.
  • Timed: FDE technical screen (edge AI): 20 questions, 45 minutes.

Idempotent vibration-feature ingest with a safe backfill

coding 2-3 h

edgefde/w1-c1 · Production Python and data pipelines

Scenario. Corvane Industrial's pump-plant gateways publish one feature record per 60-second window to Kafka. The prototype consumer duplicated windows after a broker failover and a half-finished backfill left a day at 1.3x its rows. Build a consumer and a backfill CLI that can be killed and rerun at any point without changing the numbers, and that refuse to load an incomplete day.

Task

  • Pydantic message contract for schema v1/v2 with a quarantine reason for every rejection
  • SQLite store: one-transaction batches, upsert keyed by (device, window), higher seq wins
  • Consumer that commits offsets only after the write succeeds
  • Data quality checks per day (partition, presence, completeness, unknown devices, RMS range)
  • Backfill function and CLI that fail before writing when data quality fails

Acceptance criteria

  • Crash between poll and write, or a failed write: no lost and no duplicated windows
  • Batches are atomic; redelivered bad messages quarantined once
  • 2026-10-14 backfilled any number of times gives exactly 5760 rows; 2026-10-15 fails on pump-03 completeness
  • CLI exit codes 0 / 2; ANSWER.md explains the delivery semantics
