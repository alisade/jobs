AWS FDE workbook

Hands-on coding, troubleshooting and design exercises from the forward deployed engineer's seat at Tidewater Analytics (fictional), whose multi-tenant "ask your data" product Tidewater Ask runs on Bedrock, AgentCore, Knowledge Bases, Neptune Analytics, DynamoDB, Cognito and embedded Quick Sight. One tab per study week, plus weekly self-exams. Everything grades locally and offline: no AWS account, no API keys, no Docker.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade awsfde/<id> in Claude Code from the workbooks/ folder. Quiz answers save in this browser (localStorage key wb-awsfde-v1).

How to work an exercise

  1. tools/doctor.sh awsfde once: python3, uv and jq.
  2. Open the week tab, read the card, then the folder README.
  3. cd awsfde/exercises/<id> && make setup (the first run builds the shared venv awsfde/.venv), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade awsfde/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; design exercises are graded by rubric only (the grader reports 0/0 tests and the automated row does not apply).

How the local stand-ins work

  • Python 3.12 with pytest in one shared venv; a pytest plugin blocks every network connection and sets fake AWS credentials.
  • DynamoDB, S3, SQS, STS and IAM through moto.
  • Bedrock Runtime, Knowledge Bases (bedrock-agent-runtime), bedrock-agent, AgentCore, Quick Sight and Neptune Analytics through real boto3 clients with botocore Stubber: requests are validated against the real service models, responses are recorded.
  • openCypher runs locally on networkx with grand-cypher; CloudFront caching, Knowledge Base retrieval and the Gateway are small simulators with the real request and response shapes.
  • Troubleshooting evidence (logs, configs, tickets) is generated by make setup from a deterministic replay of the broken code.

Converse tool-use loop with a guardrail, tenant-safe tools and cost logging

Throttling storm after the resilience release

troubleshooting 2 h

awsfde/w1-t1 · Bedrock: quotas, throttling and retries

Scenario. Friday's resilience release for the Tidewater Ask answer service was meant to stop errors during the Monday 09:00 login wave. On Monday a third of questions failed for ten minutes, p95 hit the 29 s gateway limit and Bedrock throttles rose 20x on 20% more traffic. Find why, before anyone asks AWS for more quota.

Task

  • Count the Bedrock calls one request can make in each release and explain where they come from
  • Rule the reserved concurrency change and the quota in or out, with evidence
  • Fix the retries: one layer, at most 4 attempts, capped full jitter, no retries on non-retryable errors
  • Return a degraded 503 with Retry-After the portal understands; verify with the replay

Acceptance criteria

  • At most 4 calls per request when every call is throttled; non-retryable errors make one call
  • Replay of 2026-11-09: error rate under 5%, p95 under 8 s, under 1.5 calls per request
  • ANSWER.md root cause backed by log, dashboard and config evidence
