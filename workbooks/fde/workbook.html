FDE Workbook - Agent Runtimes and MCP

Hands-on coding and troubleshooting exercises for the FDE study plan, built around the commerce-agents blueprint (commit fd4d592), plus a self-exam. Quiz answers save in this browser.

Overview

Twelve exercises, about two per study week: one coding, one troubleshooting. Each is a folder you solve in your editor and grade with /grade fde/<id> from the workbooks/ directory in Claude Code. Nothing calls the real Claude API: model traffic is a fake client or recorded fixtures.

Workflow

cd workbooks/fde/exercises/<id>
make setup     # shared venv + scenario (idempotent)
make test      # visible tests
# edit code, fill in ANSWER.md
# from workbooks/ in Claude Code:
/grade fde/<id>
make clean     # stop anything setup started

Don't open .grading/ before you submit: hidden tests and the reference live there. Pass mark 70/100. Troubleshooting is graded mostly on the root cause and evidence in ANSWER.md.

Environment

All exercises share one virtualenv, fde/.venv, built by make setup (_env/ensure-venv.sh) with uv. It installs the blueprint's seven packages editable from ../commerce-agents using the blueprint's own pinned requirements.txt, adds pytest, respx, hypothesis and ruff, and puts the blueprint's examples/ on sys.path so MockRetail imports. The commerce-agents repo is never modified. Point elsewhere with COMMERCE_AGENTS=/path. No Docker needed.

make -C workbooks/fde venv       # build/reuse the venv
make -C workbooks/fde distclean  # stop everything, drop the venv

What a senior answer looks like

  • Coding: the hidden tests cover failure paths, cancellation, privacy and concurrency, not just the happy path.
  • Troubleshooting: name the single root cause, show the evidence (command + output excerpt), separate trigger from cause, and rule out the red herring explicitly.
  • Trade-offs: take a position you would defend in a design review.

Self-exam

Interview-style questions on caching mechanics, MCP auth, fail-open vs fail-closed, the blueprint's architecture, and async Python. Pick an answer, press Check; the explanation appears either way. Multi-select questions say "choose all that apply" or "choose two".
