# connect/w7-t1 - Bot-to-agent handoff loses context on chat

**Type:** troubleshooting | **Estimate:** 1.5-2 hours | **Study plan:** Week 7 (bot-to-agent handoff, persistent chat, agent workspace); Week 1 (flow modules); Week 5 (Lex session attributes)

## Symptom

Since release 2026.10.06, LFG chat agents see an empty "Help desk assistant" panel when the Lex bot
hands a chat over: no summary, no intent, no slots, and a "Caller not verified" warning on every chat.
Voice handoffs are fine. Customers say they explained everything to the bot. Chat AHT is up 2m40s and
Monday 08:00 is the chat peak. Read `incident/PAGE.txt` first.

## What you have

| Path | What it is |
|---|---|
| `incident/PAGE.txt` | the ticket and the team thread (created by `make setup`) |
| `incident/release-2026.10.06.md` | release notes |
| `incident/flow-logs.jsonl` | CloudWatch flow log excerpts (one JSON per block execution, including module blocks) |
| `incident/lex-conversation-logs.jsonl` | Lex V2 conversation logs for the same sessions |
| `incident/contact-records.jsonl` | contact records (CTRs) for 2 voice and 3 chat contacts |
| `incident/agent-workspace-screens.txt` | text captures of the agent panel |
| `flows/helpdesk-voice-inbound.json`, `flows/helpdesk-chat-inbound.json` | the flows in prod (flow language) |
| `modules/lfg-handoff.json` | the new shared flow module |
| `config/resources.json` | queue, bot alias and module ARNs |

The agent app (connect/w7-c2) reads `lexIntent`, `botSummary`, `lexSlots`, `callerVerified` and
`handoffSource` from contact attributes. The bundle is generated by running this checkout's flows through
the `connect-kit` interpreter, so `make bundle` after a fix regenerates it with your fixed flows.

## Your task

1. Find the root cause and prove it with evidence from the bundle (quote log lines and records):
   where exactly the context is lost, why voice is unaffected, why UAT did not catch it, and what the
   persistent-chat ids in the thread do or do not have to do with it.
2. Fix the flows/module so chat hands over the same context as voice, keeping the shared module
   (preferred) or explaining why you inlined it. Keep routing as it is.
3. Verify with `make lint`, `make test` and `make bundle` (the regenerated screens should show the chat
   context).
4. Write `ANSWER.md`: Approach, Root cause (with evidence), Fix (and verification), Trade-offs / what you
   would do to stop this class of regression.

## Acceptance criteria (what the grader checks)

- Chat handoffs for every intent carry `lexIntent`, `botSummary`, `lexSlots`, `callerVerified` and
  `handoffSource=bot`, matching voice; unverified stays unverified.
- Chat routing unchanged; a bot timeout still reaches an agent; voice unchanged; everything lints.
- If the chat flow still uses `lfg-handoff`, the module no longer depends on data a module cannot see.
- `ANSWER.md` names the mechanism precisely, with evidence, and rules out the red herring.
