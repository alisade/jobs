Modernization workbook

Hands-on coding, troubleshooting and design exercises set in ClaimDesk, the Java monolith of Corvane Mutual Insurance (fictional), and its .NET agent portal: JDK and Jakarta upgrades, dependency remediation, reverse engineering into specs, LDAP to OIDC, characterization tests, supply chain, pod leadership and guarded migration agents. One tab per study week, plus weekly self-exams. Everything grades locally and offline.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade modernize/<id> in Claude Code from the workbooks/ folder. Quiz answers save in this browser (localStorage key wb-modernize-v1).

How to work an exercise

  1. tools/doctor.sh modernize once: JDK 21 + Maven, the dotnet SDK, python3 + uv, jq. make deps in modernize/ fills the caches.
  2. Open the week tab, read the card, then the folder README.
  3. cd modernize/exercises/<id> && make setup (downloads Maven, NuGet or Python packages once, so grading runs offline), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade modernize/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; design exercises are graded by rubric only (the grader reports 0/0 tests and the automated row does not apply).

How the local stand-ins work

  • Java exercises build with JDK 21 and Maven, run JUnit 5, and grade offline (mvn -o) from the ~/.m2 cache that make setup fills.
  • Identity: an embedded UnboundID LDAP server loaded from an LDIF snapshot, and a local token issuer with its own RSA keys and JWKS in place of Okta. No tenant, no network.
  • Servlet migration runs on embedded Tomcat (9 for javax, 10.1 for jakarta), driven by HTTP characterization tests.
  • .NET runs on the dotnet 10 SDK with xunit, restoring offline from the NuGet cache.
  • Python exercises (spec checkers, scanners, CI guards, agents) run pytest in modernize/.venv.
  • Agents use scripted model clients that replay Messages-API-shaped responses, and a fake prompt-cache API that does the cache accounting. No API key.
  • Troubleshooting exercises ship or generate evidence bundles: logs, transcripts, SBOMs, scanner output, mainframe reports.

  • Find every source of cached-prefix instability, including cross-process ones
  • Rule the model bump in or out with evidence
  • Fix build_request: stable prefix, time after the breakpoint
  • Propose the CI guard that would have caught it

Acceptance criteria

  • Prefix identical across time, listing order and skill order
  • Time still reaches the model after the breakpoint; modules do not share a prefix
  • Replay reads the cache after turn one and costs far less
  • ANSWER.md explains the mechanisms with evidence
