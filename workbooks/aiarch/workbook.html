AWS AI Architect workbook

Hands-on coding, troubleshooting and design exercises for Lighthouse, the agent platform of Harbor Point Mutual (fictional): multi-account guardrails, GitLab OIDC, Strands agents, AgentCore Runtime and Gateway in CDK, OBO identity, Cedar, AgentOps, DynamoDB state, SSM runbooks and cost. One tab per study week plus weekly self-exams. Everything grades locally and offline: no AWS account, no model API calls.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade aiarch/<id> in Claude Code from the workbooks/ folder. Quiz answers save in this browser (localStorage key wb-aiarch-v1).

How to work an exercise

  1. tools/doctor.sh aiarch once: python3, uv, node 22 (for the CDK exercise), jq.
  2. Open the week tab, read the card, then the folder README.
  3. cd aiarch/exercises/<id> && make setup (first run builds aiarch/.venv, and npm ci into aiarch/_env for w3-c1), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade aiarch/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; the design exercise is graded by rubric only (0/0 tests).

How the local stand-ins work

  • SCPs, RCPs and trust policies: small evaluators (scpsim, oidccheck) apply AWS evaluation rules to request fixtures.
  • Strands agents run for real with a scripted model provider; MCP servers run in-process with the official Python SDK.
  • CDK synthesizes offline with aws-cdk-lib/aws-bedrockagentcore and is checked with aws-cdk-lib/assertions.
  • Cedar via cedarpy; OAuth with a fake IdP (PyJWT); DynamoDB via moto; OTEL with the SDK's in-memory exporter; SSM runbooks on a local interpreter; Bedrock caching with a stub Converse client.
  • Troubleshooting evidence (logs, CloudTrail, metrics, spans) is generated by make setup into incident/.

Lighthouse org guardrails: five SCPs and one RCP

coding 2-3 h

aiarch/w1-c1 · Multi-account governance

Scenario. Harbor Point Mutual's new AWS organization for the Lighthouse agent platform has OUs and accounts but no guardrails. Security signed off region, audit, IAM-user, Bedrock model and private-access rules plus an org-boundary RCP. Write them as code and prove them against a request table with a local SCP/RCP evaluator before anything is attached for real.

  • Visible and hidden request tables give the expected decisions
  • Deny-only statements with Sids, FullAWSAccess kept, size limits, RCP shape
