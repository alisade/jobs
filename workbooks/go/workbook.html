Principal Golang Architect - Workbook

Hands-on coding and troubleshooting exercises for the Go architect study plan, plus a self-exam. Solve each exercise in your editor, then run /grade go/<id> in Claude Code from the workbooks/ folder.

Scores update after /grade; reload the page.

Overview

About two exercises per study week: one coding, one troubleshooting. Coding exercises have visible tests (make test) and hidden tests run by the grader. Troubleshooting exercises start from a genuinely broken system or a realistic artifact bundle; most of the grade is the root cause and evidence you write in ANSWER.md. Pass mark is 70/100.

How it works

  1. tools/doctor.sh go once (Go 1.26; envtest assets download on first make setup of the operator exercises).
  2. cd go/exercises/<id> && make setup, read README.md, solve, make test.
  3. Fill in ANSWER.md (Approach, Root cause for troubleshooting, Fix, Trade-offs).
  4. From workbooks/: /grade go/<id>. Reload this page.

Rules

  • Do not open .grading/ before you submit: hidden tests and the reference live there.
  • Nothing calls a paid API. LLM and MCP exercises use httptest fakes.
  • No Docker or kind needed: controllers use envtest, the mesh and database exercises use artifact bundles.
  • git checkout -- go/exercises/<id> resets an exercise.

Week 1 - Go language and idioms

Go as Go, not Python with braces: small interfaces, explicit errors, zero values that work. Exercises start at experienced-engineer-new-to-Go level. Open this week in the study plan.

codingPort snapshot-janitor from Python to idiomatic Go2 h

Northwind Freight's nightly Python EBS snapshot janitor is moving off a Jenkins box into a static Go binary run as an EKS CronJob with Pod Identity. Last quarter it deleted a snapshot backing a golden AMI and exited 0 after throttled deletes, so reviewers want explicit, testable error handling.

Task

  • Implement janitor.Run against a two-method EC2API interface (AWS SDK for Go v2; tests use a fake).
  • Finish cmd/snapshot-janitor/main.go: flags, JSON slog, SIGTERM via signal.NotifyContext, exit codes 0/1/2.
  • Fill in ANSWER.md.

Acceptance criteria

  • Paginates with an owner filter; skips retained and AMI-backed snapshots; deletes oldest first with a cap.
  • DryRunOperation and InvalidSnapshot.InUse mapped via errors.As into smithy.APIError.
  • Partial failure returns errors.Join with ErrPartialFailure and every root cause; cancellation stops promptly.
  • 14 tests (1 visible, 13 hidden) pass under -race.

Week 2 - Concurrency, testing, tooling

Goroutines, channels, context, the race detector, table tests and fuzzing. The bugs here are the ones that page you at 3am. Open this week in the study plan.

codingalbstats: fuzz-tested ALB log parser with a concurrent aggregator2.5 h

Harbor Lane is replacing a slow Python incident script, which crashed on escaped quotes in a User-Agent, with a Go CLI that reports per-target-group request counts, ELB and target 5xx counts and nearest-rank P50/P99 latency from ALB access logs.

Task

  • Implement ParseLine and Entry.Format: quoting, escapes, - values, typed *ParseError, a round-trip fuzz invariant.
  • Implement Aggregate: one reader and N errgroup workers, clean cancellation, identical results for any worker count.
  • Add table rows and fuzz seeds, run make fuzz, fill in ANSWER.md.

Acceptance criteria

  • make test passes under -race; make fuzz runs 60 s without failures.
  • Errors are typed per field and line and work with errors.Is/errors.As.
  • Deterministic report with exact percentiles; lines over 64 KiB work; cancellation returns promptly with no goroutine leak.
  • 18 tests pass.

codingMCPServer reconciler: owned resources, conditions, finalizer3 h

Lattice AI's agent-fleet-operator on EKS: teams declare an MCPServer (agents.example.dev/v1alpha1) and expect a running MCP server that the gateway discovers through the mcp-catalog ConfigMap. A hand-run script left stale catalog entries. API types, CRD (CEL, defaults, print columns), manager and envtest suite are given; you write the reconciler.

Task

  • Finalizer add/remove, deletion with a missing catalog entry, NotFound and a no-op steady state handled.
  • 16 envtest tests pass, no sleeps.

codingTrace agent tasks across Kafka with OpenTelemetry and franz-go2.5 h

At RelayPoint, task-api publishes agent.tasks events and task-runner pods consume them, but every trace stops at the Kafka hop. An earlier fix appended a traceparent header on every produce, which broke the DLQ re-publisher: re-driven records carried two headers and consumers read the stale one.

Task

  • Implement HeaderCarrier over kgo.Record headers (Set replaces, never appends).
  • Implement Producer.ProduceSync (PRODUCER span, then inject) and Consumer.Process (extract, CONSUMER span as a child).
  • Fill in ANSWER.md; tests run against franz-go's in-process kfake cluster.

Acceptance criteria

  • One trace runs end to end producer to consumer; child vs link is justified.
  • Messaging semconv attributes on both spans; baggage propagates; errors set status Error with error.type.
  • Re-producing a record leaves exactly one traceparent; providers injected, no otel.Set*.
  • 16 tests pass under -race.
