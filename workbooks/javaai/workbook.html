Java full stack + AI workbook

Hands-on coding, troubleshooting and design exercises for Kestrel Learning (fictional), an AI tutor for open university courses: a Spring Boot system of record, an Angular learner app, Gemini on Vertex AI, a Python ADK agent on Cloud Run, RAG and evals. One tab per study week, plus weekly self-exams. Everything grades locally and offline: no Google Cloud project, no API keys, models are scripted or recorded.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade javaai/<id> in Claude Code from the workbooks/ folder. Quiz answers save in this browser (localStorage key wb-javaai-v1).

How to work an exercise

  1. tools/doctor.sh javaai once: JDK 21 + Maven (Java exercises), node 22, uv, python3, jq.
  2. Open the week tab, read the card, then the folder README.
  3. cd javaai/exercises/<id> && make setup (first run downloads Maven artifacts to ~/.m2, or builds javaai/.venv / javaai/_env/node_modules), solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade javaai/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on root cause and evidence; design exercises are graded by rubric only (0/0 tests).

How the local stand-ins work

  • Java 21 with Maven: Spring Boot 3.5 with H2 in PostgreSQL mode for Cloud SQL, MockMvc and JdbcTemplate tests, Hibernate statistics for statement counts.
  • Gemini: a scripted client (Java) or recorded generateContent responses with safety ratings (Python); tokens and cost are part of the contract.
  • ADK: the agent loop, callbacks and McpToolset are modelled in small local stand-ins with the same names, so the guardrails are code you write and test.
  • FastAPI with httpx in-process; Google ID tokens signed with test-only RSA keys; Cloud Run settings checked in service.yaml.
  • MCP: the official Python SDK over an in-memory session. RAG: a deterministic embedder. Angular logic: TypeScript + RxJS with jest. SQL plans: SQLite with the same plan shapes.

Catalog API: validation, problem details and a schema that enforces itself

coding 2-3 h

javaai/w1-c1 · Java and Spring Boot

Scenario. Kestrel Learning's Spring Boot catalog API (courses, lessons, quiz items, attempts) shipped fast: bad input is stored or answered with a 500, two authors created the same slug, the learner quiz JSON carries the answer key, the list endpoint honours size=100000 and the database enforces nothing. V1 of the schema is already applied everywhere.

Task

  • Bean Validation on the request records, including a class-level constraint for answerIndex and distinct options
  • RFC 9457 problem details with an errors array; 404 and 409 mapped, races backstopped by constraints
  • A learner view without the key or explanation
  • Page-size cap and page validation
  • A V2 Flyway migration with unique, FK and CHECK constraints and a learner index; V1 untouched

Acceptance criteria

  • Hidden MockMvc tests: status codes, application/problem+json, field names in errors
  • Hidden JdbcTemplate tests prove the database rejects bad rows
  • V1 checksum unchanged, a later migration applied
  • ANSWER.md explains the two layers and a safe rollout against dirty data
