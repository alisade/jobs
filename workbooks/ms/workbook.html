Microsoft exam workbook

Hands-on coding and troubleshooting exercises plus exam-style self-exams for the three exams in the study plan: DP-700 (weeks 1-4), AB-400 (weeks 5-8) and AB-100 (weeks 9-11), plus the AI Integration page.

Scores update after /grade; reload the page. Grades come from ../grades/grades.js, written by tools/update_grades.py when you run /grade ms/<id> in Claude Code from the workbooks/ folder. Quiz answers and mock-exam results save in this browser (localStorage key wb-ms-v1).

How to work an exercise

  1. tools/doctor.sh ms once: uv, node, jq, dotnet.
  2. Open the week tab, read the card, then the folder README.
  3. cd ms/exercises/<id> && make setup, solve it, make test, fill in ANSWER.md.
  4. From workbooks/: /grade ms/<id>. Reload this page.
  5. make clean. Retry as often as you like; every attempt is kept.

Do not open .grading/ before you submit. Pass mark 70/100. Troubleshooting is graded mostly on the root cause and evidence in ANSWER.md.

How the local stand-ins work

  • Fabric Spark notebooks: polars + delta-rs (deltalake) Delta tables; no Java or PySpark needed.
  • KQL, pipeline JSON, flow definitions, solution XML, Copilot Studio YAML, connector OpenAPI: you author the artifact; the grader validates its structure and simulates its behavior.
  • Dataverse plug-ins: C# against the real Microsoft.Xrm.Sdk types (Dataverse client NuGet), tested with fakes on .NET (real plug-ins target .NET Framework 4.6.2).
  • Dataverse Web API: a local fake OData server with paging, $batch, 429 + Retry-After and change tracking.
  • No test calls a real cloud or LLM API.

Medallion incremental load with watermark, MERGE and SCD2

coding 2-3 h

ms/w1-c1 · DP-700 · Ingest and transform data (30-35%)

Scenario. Northwind Logistics lands carrier shipment events into a Fabric lakehouse every 15 minutes. The full-overwrite notebook takes 40 minutes and a resent PICKED event overwrote a DELIVERED status. Rewrite it as an idempotent incremental load with a routing-history SCD2 dimension (polars + delta-rs locally, same Delta protocol).

Task

  • Watermark control Delta table: upsert per source, never backwards, no empty commits
  • Incremental bronze read with a lookback window and schema validation (SchemaError)
  • Reject null keys/event times; dedupe latest per shipment (event_ts, then _ingest_seq)
  • Guarded Delta MERGE into silver so late older events never overwrite newer rows
  • SCD type 2 dimension over carrier + destination: ordered same-batch versions, null-safe compare, replays ignored
  • run_batch orchestration with the watermark committed last

Acceptance criteria

  • Reruns inside the lookback add no rows, versions or dimension commits
  • Empty increments create no Delta versions
  • Late-landed files are picked up; the watermark never moves backwards
  • Multiple changes in one batch produce ordered SCD2 versions with correct effective ranges
  • Schema drift raises before any write; silver history shows MERGE and time travel works
